# ポストカード（試作）

セッションの絵本（約10ページ）を、持ち帰り用のポストカード3枚（既定）にまとめて、実寸の印刷用PDFにする。絵本の生成処理（`storybook.py`・`storybook_render.py`）には手を入れず、`scripts/postcard.py` がその結果を読み直して作る。プリンター（Canon SELPHY CP1500 など）への送信はまだない。

```bash
python scripts/postcard.py logs/session_<...>.jsonl                 # -> logs/postcards/<ログ名>.pdf と .json
python scripts/postcard.py <log>.jsonl --out /tmp/cards.pdf --png /tmp/cards   # 確認用に300dpiのPNGも
python scripts/postcard.py <log>.jsonl --style poem                  # ほかのスタイル（下の表）
python scripts/postcard.py <log>.jsonl --plan /tmp/cards.json        # 手で直したプランから描き直す（LMなし）
python scripts/postcard.py <log>.jsonl --no-llm                      # LMを使わずに作る（API不要）
python scripts/postcard_items.py --list                              # 小物の一覧（下記）
```

## 何を再利用しているか

- 場面・文章・挿絵は `storybook.build_book()` の結果（絵本PDFと同じもの）。ページを場面ごとにまとめ直し、ページをまたいだ長いセリフの重複は除く。
- 挿絵は絵本に載ったものをそのまま使い、セッションごとの新しい画像は生成しない。切り抜き・白背景への合成も絵本PDFと同じ処理。
- 各カードの絵は、そのカードの場面の中で、この会話から生成した絵（`session`）を最優先し、なければ他のセッションで生成した保存済みの絵（`generated`、生成に失敗したときの代わり）、それもなければ同梱の絵（`bundled`）を使う。LMに選ばせるが、Pythonが優先順を守っているかを確かめる。いまのfootprintsでは生成される絵が前半の場面に多いので、1枚目と3枚目は同梱の絵になりやすい。
- フォントは絵本と同じ Yomogi。改行の禁則も絵本と同じ関数。

## スタイル

| | `dialogue`（既定） | `dialogue_portrait` | `poem` | `prose` |
|---|---|---|---|---|
| 向き | 横 148 × 100 mm | 縦 100 × 148 mm | 縦 | 縦 |
| 絵 | 左に大きく（最大 88 × 86 mm）。透明部分は透明のまま | 上に 60〜80 mm 角（文字の量で変わる） | 上に 80 mm 角 | 上に 76 mm 角 |
| 文章 | 実際のやりとり1往復が、絵の描かれた形をよけて流れる（下記）。右上に小物イラスト。9.5〜8 pt | 絵の下に、実際のやりとり1往復。9.5〜8 pt | 2〜4行の短い詩（ひらがな分かち書き） | 漢字かな交じりの短い文章 |
| 会話の見せ方 | 名前も「」も付けず、プーのセリフは左寄せ、参加者のセリフは右寄せ（少し暖かい色） | 同じ（1行は段の86%まで） | — | — |
| 題名・番号 | なし | なし | 下に小さく | 1枚目の上に題名、右下に番号 |
| LMが書く文 | なし（選ぶだけ） | なし（選ぶだけ） | あり | あり |

`prose` 以外は枠を付ける。既定は、はちみつ色の手描き風の二重枠（絵本の表紙の枠と同じ作り方を、印刷で鮮明なようにベクターで）。シナリオごとにリボンの枠にもできる（`dialogue` のみ、下記の `frame`）。余白は6 mm 以上（ふちなし印刷で切れる分を避ける）。

`dialogue` を既定にしたのは、LMが書いた詩や要約は「AIっぽさ」が抜けなかったため。載る言葉はすべて会話の原文で、LMはどのやりとりを載せるかを選ぶだけ。

### 文字の流し方（`dialogue`）

古い絵本の、挿絵のまわりを文字が回り込む組み方にならう（`flow_layout`）。

- 絵（と小物）の透明でない部分を0.5 mm 単位の格子にし、2.4 mm 広げて、文字が入れない場所とする。
- 文字はカードの右側（左端から58 mm より右）だけに置く。その中で、1行ごとに、その高さで右端まで続いている空き（28 mm 以上）を使う。プーのセリフはその左端から、参加者のセリフはその右端に寄せる。続きの行は、場所があれば上の行と同じ端にそろえる。
- そのため、文字の左端が絵の輪郭に沿ったり、吹き出しと頭のすき間に入ったり、プーの顔のすぐ横にプーのセリフが来たりする。
- 空きが狭い高さは飛ばす。ただし1つのセリフは途中で絵をまたがず、まとまりのまま絵の下から始め直す（「いいよ、」と「いっしょにいこうか」が絵の上と下に分かれない）。次の文節がその幅に入らないときも、文節の途中で切らずに下へ送る。
- 1〜2文字だけが次の行に残る場合は、最後の文節ごと次の行へ送る。
- 足あとの列（下記）があるときは、右端の15 mm の帯を足あとに空け、文字はその左だけに流す。
- 入りきらないときは、文字を9.5 → 9 pt、絵を100 → 90 → 80 %、最後に文字を8.5 → 8 pt の順に小さくする（`FLOW_FITS`）。文字のかたまりは、カードの高さのなるべく真ん中に来るように置く。
- 横に広い絵（茂みの絵など）では横に空きがないので、セリフは絵の上や下に来る。

### 改行の位置

単語の途中では改行しない（`phrases`・`wrap_phrases`）。文節の切れ目でだけ改行する。

- [BudouX](https://github.com/google/budoux)（Googleの改行位置用の文節分割、Apache-2.0、辞書不要）が入っていればそれを使う（`pip install budoux`）。
- 入っていなければ、簡単な規則で分ける：句読点・閉じかっこの後、開きかっこの前、ひらがなから漢字・カタカナなどに変わるところ。ただし漢字の後のひらがな1字は送りがなとみなして切らない（「見た目」）。助詞（の・は・が…）なら切る（「ウズウズの｜見た目は」）。
- ひらがなだけの長い文節（「こっちのあしあとはきみのあしとおなじおおきさだね」）が1行に入らないときは、助詞の後で切る（「…きみのあしと｜おなじ…」）。それでも入らなければ任意の位置で切る。この推測は「ぼくのは｜ちみつ」のように間違えることがあるので、BudouXを入れたほうがよい。

## やりとりの選び方（`dialogue`・`dialogue_portrait`）

1. LM（既定 `openai/gpt-5.5`、`POSTCARD_MODEL` で変更可）が、場面を順番どおり3つに分け、各カードの絵と、その絵に合うやりとりを選ぶ。
2. やりとりの形は「プー→参加者→プー」か「プー→参加者」だけ（`DIALOGUE_SHAPES`）。カードではプーを左、参加者を右に置くので、必ずプーから始めて、視線が左→右（→左）と流れるようにする。続けて交わされた発言であること。例外として、カードの場面にプー→参加者と続くやりとりが一つもない（プーがひとりで話している、イーヨーの話のはちみつを味見する場面など）ときだけ、プーの発言1つにする。
3. 絵とやりとりを食いちがわせないため、やりとりは必ずその絵の場面の中から選ぶ。同梱の絵や他のセッションの生成絵は場面のはじまり（地の文の瞬間）を描いたものなので、その場面の最初の4つの発言（`NEAR_START`）のどれかから始まるやりとりに限る。この会話から生成した絵は場面の会話全体から描いているので、その場面のどのやりとりでもよい（`opening_window`）。締めくくり（本の最後の場面）だけは、プーの締めくくりのセリフに参加者が答えていないことが多いので、同じカードに入る直前の場面の最後の4つの発言から始まるやりとり（締めくくり直前の会話）も選べる。形（プーから始まる）は同じ。イーヨーの例で、はちみつが空になった絵の横に、同じ場面の終わりのほうのリボンと風船の色の話が載ってしまったために足した。
4. 発言は文ごとに分けて渡し、LMは発言のidと、使う文の連続した範囲だけを返す。長いプーのセリフは文単位で短くなるが、書きかえはできない。句読点だけは整える（音声認識の「，」「、、」を「、」に）。
5. 参加者の発言は音声認識の結果なので、言いよどみや誤認識・あいづちだけのものは避け、意味のはっきりした、物語を動かした発言を含むやりとりを選ぶよう指示している。
6. 選んだやりとりが絵に合っているかを、LMに絵そのもの（512 px に縮めたもの）を見せて判定させる（`check_pictures_match`）。会話が絵の状況そのものか、その状況を受けた話（「空っぽの壺をどうしよう」）ならよく、関係のない別の話題や絵と矛盾する話（空の壺の絵に「ハチミツの入った壺を贈ろう」）は差し戻す。参加者の発言の誤認識は理由にしない。細かい対応は前の項の「場面の最初のほう」の決まりが受け持ち、こちらは明らかな食いちがいを拾う安全網（2026-11-07、イーヨーとfootprintsの組み合わせで、矛盾は拾い、正しい組は通ることを確かめた。「リボンや風船の準備」の話は空の壺の絵でも通る）。
7. Pythonが確かめる（`build_dialogue_card`・`check_dialogue_plan`）：場面の分け方、絵の優先順、発言が絵の場面の選べる範囲のものか、形と連続、カードに入るか、参加者の発言が全体で1つ以上あるか。問題があれば（6.の絵の判定も含めて）、前回の案と問題点を渡して選び直させる（最大3回）。
8. だめなら、LMを使わず、各カードの絵の場面の選べる範囲で、プーのセリフの直後に参加者がいちばん長く話した発言を選び、その直前のプーのセリフ（最後の1文、たいてい問いかけ）と、直後のプーの返事（入るまで文を削る）を載せる（`extractive`）。そういうやりとりがないカードは、プーの最初の発言の1文目だけ。

## 小物イラスト

シナリオごとに `config/postcard/<シナリオ>.json` に書く（シナリオを増やすときはファイルを1つ足すだけ）。

- `items`：小物の名前と中身。中身は次のどれか。
  - `{"file": ...}`：既存の絵をそのまま使う。
  - `{"combine": [{"file": ..., "half": "left"}, ...]}`：既存の絵の左右の半分を並べる。`scripts/postcard_items.py` が切り貼りで作る（描画はしない）。
  - `{"prompt": ...}`：`scripts/postcard_items.py` が、`style_reference` の挿絵を画風の手本にして `gpt-image-1.5` で透明背景に描く（シナリオごとに一度。セッションごとではない）。
  - `{"trail": [小物, ...], "count": 6, "size_mm": 7, "wiggle_mm": 2.5}`：右端の帯に、上から下へ少し蛇行しながら、左右交互に少し傾けて並べる足あとの列。挙げた小物を順番に使う（肉球・楕円なら交互）。
  - 1つの小物には `anchor`（`top_right` / `top_left` / `bottom_right` / `bottom_left`、枠の内側の四隅）と `size_mm` を付けて、置き場所と大きさを変えられる。
- `placement`：そのシナリオの `anchor`・`size_mm` の既定。
- `frame`（任意）：カードの枠。書かなければ、はちみつ色の手描き風の二重線。`{"style": "lines", "color": [r, g, b]}` で二重線の色を変えられる。`{"style": "ribbon", "color": [r, g, b], "bow": 小物, "bow_anchor": "top_left", "bow_size_mm": 24}` で、細いリボン（幅2.2 mm）が角のリボン結び（小物の絵）から出てカードをひと回りし、また結び目に戻る（つなぎ目は結び目の下に隠れる）。リボンはゆるく波打ちながら、ところどころでねじれて（幅が細くなって）裏返り、裏側は少し濃い色になる。インクの縁取りは結び目の絵に合わせた。ベクターで描くので印刷で鮮明。波・ねじれの間隔は `RIBBON_*` 定数。文字はリボン結びをよける。
- `beats`：場面（beat）ごとに出す小物の名前。`null` にすると、その場面の絵を使うカードには小物を出さない（ほかの場面の小物でも代わりにしない）。footprints の `fourth_animal` は絵が足あとでいっぱいなので `null`。

```bash
python scripts/postcard_items.py --list                    # シナリオ・場面ごとに、どの小物をどこに出すか
python scripts/postcard_items.py --scenario footprints     # combine / prompt の小物を作る（ないものだけ）
```

作ったものは256色PNGで `assets/storybook/<シナリオ>/postcard_items/` に置く。カードには、その絵の場面の小物（なければカードの場面のうち最初にあるもの）を出す。ないものは出さないだけ。小物の置き場所・大きさはプランの `.json`（`item_anchor`・`item_size_mm`）にも残るので、1枚だけ直して `--plan` で描き直すこともできる。

- footprints：枠は足あとと同じ青灰色の二重線（`frame`、足あとの絵の輪郭と影のあいだの色 (0.55, 0.67, 0.78)）。小物は、挿絵生成用の参考画像の足あと（`paw_print_reference.png`・`oval_print_reference.png` の左半分を1つずつ切り出したもの）を、足あとの列にする。足あとが増えるまでは肉球だけ、気づき以降は肉球と楕円が交互（ふたりで歩いた足あと）。描いた小物（雪の結晶、吹き出しなど）は、吹き出しが小物として不自然などの理由でやめた。
- eeyore_birthday：枠は水色のリボン（`frame`）で、左上に水色のリボン結び（`ribbon_bow`、2026-11-07 に描いた）。小物は右上に1つ（16 mm）。贈り物の箱（はじまり）、はちみつの壺（贈り物に決めた）、はちみつのスプーン（味見）、空の壺（食べてしまった）、風船（締めくくり）。2026-11-07 に `gpt-image-1.5` で描いた（5つとも1回で成功）。

## 詩・文章のまとめ方（`poem`・`prose`）

1. LMが場面を3つに分け、各カードの絵と文章を書く。発言はLMに書き写させず、`{q番号}` で指させてPythonが原文を差し込む。
2. Pythonが確かめる（`check_plan`）：場面の分け方、絵の優先順、「」の中が会話にある言葉か（句読点・記号の違いは許す）、引用の数、長さ、カードに入るか、参加者の発言が全体で1つ以上あるか。
3. 別のLM呼び出しで、会話にない出来事・気持ち（「笑った」など）、順番や因果の入れかわり、話者の取りちがえ、先の場面の先取りを探す。省略や、事実を述べていない詩的な表現は問題にしない。
4. 問題があれば直させる（最大3回）。だめなら絵本の文だけで作る（`extractive`）。

出力の `.json` に、スタイル、どの方法で作ったか（`source`）、各カードの場面範囲・絵・小物・文章が残る。手で直して `--plan` で描き直せる。

## 確認したこと（2026-11-07）

- 長めのログ（footprints 3・イーヨー 3、2026-11-07）：6セッションとも1回目で通った。イーヨーの3枚目は、締めくくりの例外を入れる前は3セッションともプーの発言だけだったが、入れたあとは締めくくり直前のやりとりになった（例：あなた「じゃあ、ピグレットとイーヨーにドーナツを買うのを忘れないようにしよう！」）。
- `dialogue`（イーヨー）：保存済みの例 `eeyore_ribbon_and_balloon_color_2026-09-22.jsonl` で、はちみつを味見する場面にやりとりがなく、プーの発言1つの例外を入れる前は3回とも通らなかった。入れたあとは1回目で通った。
- `dialogue`：「プー→参加者→プー」に限ってからは、footprints 2セッションとも1回目で通り、6枚とも3つの発言になった（例：プー「きみも一緒に来てくれない？」／あなた「いくいく！」／プー「やった！」）。それ以前は footprints 2セッションで、`gpt-5.5` が1回目・3回目で通った（3回目のほうは、1・2回目で発言のidの代わりに本文を返していた。いまは本文でも受け付ける）。PDFは3ページ・各148 × 100 mm。選ばれたやりとりの例：あなた「きっとレインボー色だよ！」／プー「レインボー色かあ！」。
- `prose`：footprints 3セッション・イーヨー1セッションで、1回目で通った。`gpt-4o` では会話にない出来事が入り、4セッションとも `extractive` に落ちた。
- `poem`：footprints 1セッション・イーヨー1セッションで、1〜2回で通った。
- 実際に印刷しての確認はまだ。A4などに試し刷りするときは、PDFビューアで「実際のサイズ」（拡大縮小なし）を選ぶ。

## 未対応

- SELPHY への送信、ふちなし用の塗り足し（いまは白地なので不要）。
- 枚数を1〜2枚にする場合のレイアウト調整（`--cards` で枚数は変えられる）。
- eeyore_birthday の小物イラスト。
- 参加者の発言の選び方はLMの判断に任せている。誤認識だらけの発言しかない場合は、その発言が入ることがある。
