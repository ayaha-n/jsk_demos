# Web UI の公開範囲と外部公開

Web UI の起動方法の要点は README にある。ここでは、どこから何が見られるかと、`--public` での外部公開の詳細をまとめる。

## どこから何が使えるか

| | この PC（`127.0.0.1`） | 同じネットワークの別マシン（`--host 0.0.0.0`） | `--public` のトンネル経由 |
|---|---|---|---|
| 会話 | ○ | ○（トークン） | ○（キー） |
| 自分のセッションの絵本・PDF（「絵本を見る」） | ○ | ○（トークン＋セッションID） | ○（キー＋セッションID） |
| 過去ログ・過去ログの絵本と PDF | ○ | × | × |
| タブレットへの書き込み（`--storybook-eink`） | ○ | × | × |

- 「この PC」かどうかは TCP の接続元アドレスだけで判断する。転送ヘッダ（`X-Forwarded-For` など）は誰でも偽れるので使わない。
- 同じ PC でも、自分の IP アドレス（`http://192.168.x.x:8080/` など）で開くと「別マシン」扱いになる。
- 自分の絵本は、ブラウザだけが知るランダムなセッションID（32文字）で開く。他人のセッションや過去ログの一覧には届かない。セッションはサーバが保持している間（切断後 `--session-ttl`、既定10分）だけ見られる。
- 同じネットワーク（Wi-Fi など）の外からは、`--host 0.0.0.0` だけでは届かない。外から使うなら `--public`（下）か、Tailscale などの VPN を使う。

## 外部公開（--public）

`--public` を付けると、[Cloudflare quick tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/) で Web UI に公開用の HTTPS アドレスを付ける（アカウント不要）。

```bash
python scripts/web_server.py --scenario eeyore_birthday --storybook-eink --public
# Web UI: http://127.0.0.1:8080/?token=<キー>
# 公開URL: https://<ランダムな単語>.trycloudflare.com/?token=<キー>
```

- キーは `POOH_WEB_TOKEN`、未設定なら起動ごとにランダムに作る。表示するのはこの端末だけで、ファイルやログには書かない。
- 公開アドレスは起動ごとにランダムで、サーバを止める（Ctrl+C）とトンネルも止まる。
- トンネル経由でできるのは会話と、自分のセッションの絵本・PDF（「絵本を見る」）だけ。過去ログの一覧・閲覧・過去ログの絵本と PDF は拒否し（403）、「過去ログ」ボタンも出さない。セッションはタブレットに書かない。
- トンネルはサーバに `127.0.0.1` から接続してくるので、IP では外部と区別できない。トンネル専用のポートを割り当て、そのポートに着いた要求を外部として扱う。転送ヘッダは誰でも偽れるので使わない。
- `cloudflared` は PATH か、このディレクトリの `.tools/`（git 対象外）から探す:

  ```bash
  mkdir -p .tools && curl -fsSL -o .tools/cloudflared \
    https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
  chmod +x .tools/cloudflared
  ```

### 固定リンク（任意）

quick tunnel のアドレスは起動ごとに変わる。固定のリンクを配りたいときは、Cloudflare Workers（無料）に転送役を置く（`scripts/public_link.py`）。リンクはシナリオごとに `https://<名前>.<サブドメイン>.workers.dev/<シナリオ>/?token=<キー>`（例: `…/footprints/?token=…`、`…/eeyore_birthday/?token=…`）で、名前もサブドメインも自分で決めるので、個人のアカウント名は出ない。開くと、そのシナリオで動いているサーバのトンネルへ、残りのパスと `?token=` を付けたまま転送する。

- `web_server.py --public` は、トンネルが立ち上がると自分のシナリオの行き先を Workers KV に書き、`固定リンク: …` を表示する。止めるとその行き先を消し、そのリンクは「いまは公開していません」と出す。シナリオごとに別のサーバ（`--port` を分ける）を同時に動かしてよい。
- Workers KV は値を1分ほどキャッシュするので、起動し直した直後は、少しのあいだ前のアドレスに転送されることがある。
- キーも固定する（`POOH_WEB_TOKEN` を決めておく）。でないと、リンクの `?token=` が起動ごとに変わる。
- 設定（アカウントID・KV の ID・リンク）は `.tools/public_link.json`（git 対象外）、API トークンは環境変数 `CLOUDFLARE_API_TOKEN` だけに置く。トークンを渡さずに起動すれば、固定リンクは使わず、これまでどおり。

一度だけの準備:

1. [Cloudflare](https://dash.cloudflare.com/sign-up) に無料アカウントを作る。
2. 「Workers & Pages」を開き、`workers.dev` のサブドメインを決める（リンクに出るので、個人名でないものにする）。同じ画面の右側にアカウント ID が出る。
3. 「My Profile」→「API Tokens」→「Create Token」→「Create Custom Token」で、権限を「Account / Workers Scripts / Edit」と「Account / Workers KV Storage / Edit」の2つにしたトークンを作る。
4. このディレクトリで:

   ```bash
   export CLOUDFLARE_API_TOKEN=<トークン>
   python scripts/public_link.py setup --account-id <アカウントID> --name pooh
   # 固定リンク: https://pooh.<サブドメイン>.workers.dev/<シナリオ>/?token=<POOH_WEB_TOKEN>
   ```

以後は `CLOUDFLARE_API_TOKEN` と `POOH_WEB_TOKEN` を設定して `--public` で起動するだけ。`python scripts/public_link.py off <シナリオ>` で、サーバを止めずにそのシナリオの行き先だけ消せる。

### 公開するときの注意

- URL とキーを知っている人は、この PC の OpenAI API キーで会話できる。キーは参加者にだけ渡し、OpenAI の管理画面で利用上限を決めておく。
- 同時セッションは `--max-sessions`（既定20）まで。外から埋められると本番の参加者が入れなくなる。
- 会話は研究データなので、外部経由で扱うことが同意の範囲や倫理審査の条件に合うか確認する。
- 同じ PC にリバースプロキシ（nginx など）を挟まないこと。接続元がすべて `127.0.0.1` に見え、過去ログの「この PC からのみ」が効かなくなる。
- 決まった少人数だけが使うなら、Tailscale などの VPN で同じネットワークに入るほうが安全。

## 3Dのクマ（試作）

会話画面の上に、外部ライブラリ・モデルのダウンロードを必要としない
WebGLのクマを表示する。ドラッグまたは左右キーで回転、Homeキーで初期の向きに戻す。
操作ラベルや部位別ボタンは表示せず、OSの動きを減らす設定に従う。
WebGLが使えない端末でも会話は使える。

`web/bear.js` が現在の会話の `.message.pooh .details` にある動作行を読み取り、
腕の上げ下げ・手振り・あご／口に手を当てる・指さし・onegai、首のtilt／nod、
眉のsad／surprisedを約6秒間表示する。未知の動作は通常の姿勢になる。
実機動作の正確な再現、鼻の動き、arm_nextの連続動作、音声との同期は未対応。
会話の再接続で履歴が描画される場合は、最後の応答の動きを表示する。

これは対面に近い存在感を検討するための簡易モデルで、対面条件と同等とするものではない。
既存の `web/app.js` との同時編集を避けるためDOMを接続点にしているので、
詳細の表示形式を変える際はこのアダプタも合わせて更新する。

モデルの座り姿・体型はぬいぐるみのスキャンデータ（STL）を、配色は
`assets/storybook/bear-reference.png` を参考にしている。
STLのスキャン用台座や周辺の破片は再現せず、前に出した足、
お腹の前に寄せた腕、丸い体と耳を滑らかな立体で表現する。
つやを抑えた陰影と細かな表面の粒でぬいぐるみらしい質感を付けている。
画像からの自動3D復元ではなく、挿絵の輪郭や毛並みを完全に再現するものではない。

頭・左右の腕・お腹・左右の足をクリック／タップすると、会話入力と独立した
`touch` メッセージを送る。サーバは部位を検証し、実機の観測と共通の
`NarrativeSession.observe()` に「参加者がプーの頭に触れた」などを渡す。
返答の生成や会話欄への表示は行わず、`source: observed` のログと絵本に反映する。
ROS relayは不要。実機センサーのイベントを直接発火するものではない。
当たり判定は体の楕円体と、曲面の手足に沿わせた複数の判定領域との交差で、手前の部位を選ぶ。
8pxを超える移動は回転として扱い、触る行動を送らない。
接続中かつセッション継続中なら応答待ちでも送信でき、文字入力には触れない。
生成中に届いたタッチはそのターンの処理完了後に受信順で記録するため、
絵本上の順序は厳密なタップ時刻ではなく、サーバでの処理順になる。
切断中・終了後は送信しない。
部位別ボタンは設けず、モデルの部位を直接タップする。
部位判定と入力の検証は `node tests/test_bear.cjs` で実行する。

腕の付け根は低めの胸の内側に固定し、腕を上げても胴体とつながるようにしている。

タップが記録されるとサーバから `touch_recorded` が返り、クマが動作で反応する。
色は変えない。反応候補は pooh_body の `proximity_listener_array_timer.py` の
`choose_motion_for_part()` に合わせている。
頭・お腹・足は tilt、left_hand_chin、right_hand_mouth、onegai から組み合わせを選ぶ。
右腕は tilt または left_hand_chin、左腕は tilt または right_hand_mouth で反応する。
眉は normal／happy／surprised／変更なしの候補から選ぶ（Webの happy は通常と同じ表示）。
反応動作には全身共通の5秒のクールダウンがあり、動作は約6秒表示する。
クールダウン中もタップの記録は続く。
センサー値のしきい値・連続検出・動作による誤検出抑制は、明示的なタップ入力には適用しない。
会話欄には接触を追加しない。古いサーバで接触機能が確認できない場合は、
タップ時に再起動を案内する。Pythonの変更にはWebサーバの再起動が必要で、
ブラウザの再読み込みだけではサーバの処理は更新されない。

## クラウドソーシング用の完了確認（--crowdsourcing）

```bash
python scripts/web_server.py --scenario footprints --crowdsourcing --passphrase アイコトバ --public
# または --scenario eeyore_birthday
```

`--crowdsourcing` を付けたときだけ、次の流れに切り替わる。
通常起動時の終了操作・自動終了・絵本表示には完了確認を加えない。

1. ゴールまでは「終了して絵本を見る」を無効にする。ゴールは足跡の正体判明
   （controller.state.resolved）、誕生日の振り返り到達（story_wrap_up発生）。
   LLMで新しいゴール判定を行うのではなく、既存の物語状態を使う。
2. ゴールに達すると終了ボタンを目立つ色にし、UIに次の案内を出す。
   「お話がひと区切りつきました。『終了して絵本を見る』から、今回のお話を絵本で振り返れます。」
   プーの発話やモデルへの入力には加えない。ゴール後の無操作による自動終了は止める。
3. 終了後、絵本の挿絵がすべて用意され、ブラウザでも画像を読み込んでから読了確認を始める。
   絵本の末尾が画面に表示されると「絵本を読み終えた」が有効になる。
4. 読了ボタンを押すと、セッションIDとは別のランダムな完了コードを発行する。
   コピーボタンで取得して、クラウドソーシングの回答欄に提出してもらう。
5. `--passphrase` を付けたときは、完了コードの下に合言葉も出す。合言葉は全員同じで、
   回答欄に入力してもらい、クラウドソーシング側の正解チェックに使う。
   回ごとに起動時の引数で変える（起動時に「合言葉: …」と表示される）。
   付けなければ出さない。

ゴール前でも発話による終了（「さようなら」など）は受け付ける。
その場合も絵本の読了確認をすれば完了コードを発行し、途中終了かどうかは記録で区別する。
「はじめから」ボタンは重複提出・完了コードの取りこぼしを避けるため非表示にする
（新しいセッションは前のセッションの読了状態を引き継がず、別の完了コードになるため）。
完了コードは1セッションに1つで、同じタブの再読み込みで復元できる。
発行済みコードはセッションTTLやサーバ再起動後も保存ファイルから復元できる
（同じログ保存先を使い、公開時のアクセストークンが変わった場合は新しいURLで開く）。
未完了の会話・絵本の再開自体は、従来どおり生存中のセッションに限る。

進捗とコードは `logs/crowdsourcing/<session_id>.json` に保存する
（`POOH_LOG_DIR` を変えた場合はその配下）。`session_id`、`scenario`、`log_name`で
会話ログと対応づけ、開始・ゴール到達・終了・絵本表示・最終ページ到達の申告・読了確認の
UTC時刻と、`ended_before_goal`、`completion_code`、表示した`passphrase`を保持する。
再読み込みで復元したときは、サーバを別の合言葉で起動し直していても、そのとき出した合言葉を出す。

完了コードはランダムな64ビット（16進16桁）なので、セッション同士でかぶることは実際上ない。
提出された完了コードは、`logs/crowdsourcing/` の中で同じ `completion_code` を持つファイルを探せば
セッションと会話ログ（`log_name`）に対応づけられる
（例: `grep -l ABCD-1234-… logs/crowdsourcing/*.json`）。
最終ページへの到達はブラウザからの申告であり、文章を読んだことの証明ではない。
サーバでも終了済み・絵本の準備完了・同じ版の絵本を開いたこと・最終ページ申告を確認してから
コードを発行する。提出されたコードだけで絵本や会話へアクセスすることはできない。

関連テスト: `python -m unittest discover -s tests -p test_crowdsourcing.py`。

## 音声合成（--tts-server-url、試作）

```bash
python scripts/web_server.py --scenario footprints --tts-server-url http://127.0.0.1:8000
```

`--tts-server-url`（または環境変数 `POOH_TTS_SERVER_URL`）を指定したときだけ、
プーの発話をStyle-Bert-VITS2のeditorサーバー（`server_editor.py`、ロボットの声と同じ
`pooh_body/scripts/style_bert_vits2_tts.py` 相当の設定）で音声合成し、ブラウザで再生する。
指定しない場合はテキストのみで、`--crowdsourcing` など他の機能とは独立に切り替えられる。

発話ごとに音声を順番に再生する（重ならない）。ブラウザの自動再生ポリシーにより、
直前のユーザー操作とは別のタイミングで届く発話（WebSocket経由のため、送信ボタンの
クリックそのものの範囲外になる）は再生がブロックされることがある。その場合は
読み捨てず、次に画面のどこかをタップしたタイミングで再試行する。

ロボット版の `~speaking`（最後の一文を読み終えるまで真のまま）と同じく、
音声の再生中（自動再生ポリシーでブロックされていない間）は入力・送信・終了を
いったん無効にする（画面表示では特に知らせない）。テキストだけで会話が
音声の読み上げを追い越さないようにするため。`--tts-server-url` を指定しない
場合はこの制約も発生しない。

音声合成に失敗した場合（サーバ未起動・タイムアウトなど）は、該当の発話だけ
音声なしでテキストのみ表示する。挿絵と同じく、フォールバック音声や再試行は行わない。
合成結果はテキスト＋音声設定ごとにプロセス内メモリでキャッシュする
（固定文は参加者間で共有され、サーバ再起動まで再利用される）。

現時点ではTTSサーバーは単一プロセスを前提としており、常駐化・複数プロセスでの
負荷分散は別途必要（クラウドソーシング規模での運用はまだ検証中）。

関連テスト: `python -m unittest discover -s tests -p test_web_tts.py`、
`python -m unittest tests.test_web_server.TTSTests tests.test_web_server.NoTTSTests`。

### クマを表示できない環境での案内

WebGLの初期化・シェーダーのコンパイル／リンク・コンテキスト喪失の失敗時は、
「クマを表示できませんでした。会話は続けられます。」という短い案内を残す。
接触操作は使えないが、会話と絵本の操作は継続できる。
技術的な「表示エラーの詳細」は既存の `local-only-feature` と同じ接続元判定で、
このPCのループバック接続から開いた場合だけ画面に表示する。
LAN・公開トンネル経由では詳細欄をCSSで非表示にする（診断情報の機密保護ではない）。
開発者コンソールには接続元によらず `[bear] 3D rendering unavailable` を出す。
原因調査で使った初期化条件ごとのエラー・ブラウザー情報は、このローカル用の詳細に残す。
