- 確認対象: v43（`pooh_44bc0a01dcd2654e3ba4`）、v44（`pooh_82d052320442ee4fcb87`）、
  `logs/session_20261020T222902617294_b0688648.jsonl`。

プーが蜂蜜壺を贈ると言った直後の「風船はどうかな」を、分類段（`honey_requests`）が
`decline_honey_jar_gift` と判定すると、生成せずに固定セリフ

答えさせると、v43 では2回、v44 では9回だった（指示の違いは生成段だけで、分類段は同じ）。

「風船はどうかな」は、`decline_honey_jar_gift` の説明（別の贈り物に置き換えようとした場合）に
当てはまるとも読めるので、判定そのものの誤りとは言い切れない。

  取り下げずに一緒に贈る形で受け止める（再生で17回中17回）。分類段の説明と例の変更と

## 空になった壺をどうするかが、参加者の決定なしに片付いてしまう

- 記録日: 2026-10-20
- 状態: 実ログと再生で確認済み。原因は未特定で、現時点では修正しない。
- 確認対象: v43（`pooh_44bc0a01dcd2654e3ba4`）、
  `logs/session_20261020T222902617294_b0688648.jsonl`。

蜂蜜を食べた後の「空になった壺をどうするか」が、参加者が決めないまま片付く。現れ方は2通りある。

- プーが自分で決める: 上のログでは、壺の話をしていない「プーさんはハチミツが好きなの？」に
  プーが「赤い風船とつぼを持って行こう！」と答え、`give_empty_jar` が付いて
  「空になった壺をどうするか：あげる」になった。次のターンで締め（`story_wrap_up`）が起きた。
- 判定なしに消える: 同じ10入力を元ログの時刻で最後まで会話させた再生（v43 で2回、
  `situation_update` を解釈段に移した試作 v44 で2回）では、4回とも「リボンもつけようよ」の
  ターンで、`give_empty_jar` も `not_give_empty_jar` も付かないまま未解決から消え、その直後に
  締めが起きた。決まったことには壺の扱いが残らない回もある。

壺の扱いは物語の山場の一つなので、参加者が関わらずに決まると体験が薄くなる。生成段が壺を
贈る前提で話を進めているのか、状態の差分が未解決を消しすぎているのかは切り分けていない。

## 「「…」と言って、…」の形の入力は、絵本で発話部分しか残らない

- 記録日: 2026-10-19
- 状態: 実害は未確認。Web UI でこの形を入力した場合にだけ起こるので、現時点では修正しない。
- 確認対象: `scripts/storybook.py` の `spoken_part()`。

ROS 側（pooh_body の `handover_vision_relay.py`）は、差し出された物をカメラで見つけると
発話を「「はちみつ どうぞ」と言って、はちみつの壺をプーに差し出す」の形で送り、
差し出したこと自体は直前に出来事（source `observed`）として記録する。絵本では出来事を
地の文で語るため、この形の入力は「」の中だけを参加者の発話として書く。

この切り出しは入力元を区別せず、すべての参加者入力にかかる。Web UI（やターミナル）で
参加者が「「こんにちは」と言って、手を振る」と入力すると、絵本には
「「こんにちは」と、あなたは いいました。」とだけ書かれ、「手を振る」は残らない。
ログと物語の状態には入力全体が残る。

問題になる場合は、直前に `observed` の記録がある入力だけを切り出すようにする。

## 応答の差し替えにキーワードの決め打ちが残っている

- 記録日: 2026-10-19
- 状態: メモのみ。外すかどうかは未決定。
- 確認対象: `enforce_response_invariants`（`599a9d92`、2026-09-22 から）と、その条件を写した
  `response_may_be_replaced`（`81acf02c`）。

生成したセリフを、文字列の決め打ちで固定セリフに差し替えるガードが2つある。どちらも観測した
失敗を1パターンだけ塞いだもので、言い方が変わると効かない。

- 参加者の発話に「うーん」「迷」「まよう」「どうしよう」「わからない」のどれかがあり、贈り物が
  未決定で、生成セリフに「？」「どう思う」などの問い返しがあると、蜂蜜壺を提案する固定セリフ
  （`HONEY_PROPOSAL_FALLBACK_RESPONSE`）にする。
- 参加者の発話がちょうど「いいね」で、履歴に「風船」がないのに生成セリフに「風船」があると、
  「うん、そうしよう。イーヨーが喜んでくれるといいなあ。」にする。「いいね！」「それいいね」では
  効かず、対象の小道具も風船だけ。

セリフは interpret の前にロボットへ送るので、差し替えると話し終えたセリフを取り消せない。
そのため `response_may_be_replaced` が同じ条件の前半（入力と状態だけで分かる部分）を見て、
該当するターンは最後にまとめて送る。
ガードを外すなら、`response_may_be_replaced` の該当部分も一緒に外す。外す前に、生成段の
指示（参加者の同意や行動を決めつけない、捏造しない）と例で同じ失敗が起きないかを確かめる。
