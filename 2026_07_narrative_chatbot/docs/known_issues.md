約束が状態に反映される。アクションを消すこと自体を確定バグとは扱わない。

## `propose_honey_jar_gift` の主体が解釈段と Python で食い違っている

- 記録日: 2026-09-25
- 状態: 食い違いのメモのみ。実会話での不具合は未確認。現時点では修正しない。
- 確認対象: `InterpretTurn.narrative_actions` の説明と `HoneyGiftEventController` の扱い。

`InterpretTurn` の説明では、`propose_honey_jar_gift` は「ハチミツの入った壺を贈り物の
候補として、プーまたは参加者が提案したが、まだ決まっていない場合」に返す。
一方 Python は、この提案を「プー自身の提案＝プーの贈り物として即決定」として扱う。

そのため、参加者が「ハチミツの壺をあげたら？」と候補を挙げただけでも、プーの贈り物が
決まったことになりうる。プー自身の贈り物はプーが決めるという方針と、どちらに揃えるかは
未決定。実会話で問題が観測された場合に、そのログをもとに再検討する。

## 固定セリフへの差し替えで、参加者の正当な決定もそのターンは記録されない

- 記録日: 2026-09-25
- 状態: 承知のうえで選んだトレードオフ。現時点では修正しない。
- 確認対象: `NarrativeSession.submit()` の差し替え処理（`response_replaced`）。

想定例:

> プー: そうだ！ぼくは、イーヨーにハチミツの壺を贈ることにしよう。
> 参加者: ハチミツはいらないよ、ケーキにしよう。

解釈段は `decline_honey_jar_gift` と「イーヨーに何をあげるか＝ケーキ」を返すが、応答を
固定セリフ（`eeyore_birthday.honey_gift_kept`）に差し替えると、そのターンのモデルの判断は
すべて破棄するため、「ケーキ」は【決まったこと】に入らない。

`SettledDetail` は topic/value しか持たず、参加者の発言由来か、破棄した生成文由来かを
区別できない。生成文だけが勝手に決めた内容を残さないことを優先した。

影響は限定的と考えている。参加者の発言は対話履歴（直近12ターン）には残る。締めの条件は
蜂蜜を食べた後の決定だけを数えるため、この時点の決定は締めに影響しない。固定セリフも
ケーキに触れていない。長い会話で履歴から外れた後に参加者の贈り物を忘れる問題が観測
された場合に、決定の由来を区別する方法を再検討する。

## 「ここにあるもので、なにができるかな。」を独り言として扱っている

- 記録日: 2026-09-25
- 状態: 独り言扱いで確定。問題が観測されたら再検討する。
- 確認対象: `scripts/pooh_eeyore_examples.py` 場面1bのケーキ提案の例。

ケーキを焼こうという提案への例の応答「ケーキ、いいなあ。想像しただけで、おなかがなっちゃった。
ここにあるもので、なにができるかな。」は、`question_kind` を指定しておらず `none`（独り言）になる。
参加者への問いかけとしては扱わないため、返事待ちの間のイベント保留（awaiting_reply）は働かない。
参加者に新しい案を求める問いかけを繰り返さない方針とも整合する。

参加者がこれを問いかけと受け取って答えようとしている間に、物語のイベントが割り込むといった
問題が観測された場合に、質問として明示ラベルを付けるか文言を変えるかを再検討する。

## プーが「このあたりを一緒に探してみよう」とその場で探そうとすることがある

- 記録日: 2026-09-25
- 状態: 許容範囲（ぎりぎり可）としてメモのみ。現時点では修正しない。
- 確認対象: v40（`pooh_2b70a4c75b1c7778ce00`）での再生。

場所を移動しない・その場でできないことを今やろうとしない、という指示と例を加えた後の再生で、
「どこだろう...」「いきたい！つれていって」に対して「このあたりに一緒に探してみようか」
「一緒にこのあたりを探してみよう！」のように、場所は変えずにその場でアザミを探そうとする
応答が出た。ロボットは実際には探せないが、場所の移動や「あとで一緒に」の約束はしておらず、
許容範囲とした。「ぼくも手伝うね」という応答も一度出ている。

実際の参加者が探す行動を始めようとして会話が止まるなどの問題が観測された場合に、
想像として受け止める例（「どこだろう...」への応答など）の追加を検討する。
